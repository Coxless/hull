# hull-terminal コンセプト

Oct 27, 2026 · @Coxless

## 概要

hull は、**Ubuntu 専用に削った、いちばん速いターミナル**です。足りない機能はプラグインで足します。

hull は船の「船体」です。本体は船体だけにし、帆や積荷（機能）は外から積みます。

- 本体は、限りなく小さく速くする
- タブ・分割・セッションは持たず、tmux に任せる
- 本体にない機能は、プラグインで足す
- 競合は alacritty、ghostty、foot

### 前のコンセプトからの変更

v0.2 までの hull は、コマンドと出力をブロックで扱うチャット履歴型のターミナル（Tauri、デーモン、セッション保持）でした。Oct 27, 2026 に方向を変え、同じリポジトリで1から作り直すことにしました。それまでの実装（`app/`、`crates/daemon`、`crates/protocol`）と `docs/phases/` は消しました。セッションの保持は tmux に、Claude Code の入力待ちの通知はプラグインに任せます。

バージョン番号は前のものから続け、作り直した最初のリリースを v0.3.0 とします。v0.1 / v0.2 のタグと `.deb` がすでにあるので、振り直すと区別がつかなくなるためです。

## 勝ち筋

alacritty は「機能を足さない」ことで速さを保っていますが、そのせいで欲しい機能があっても手に入りません。ghostty は機能が豊富でよくできていますが、macOS とクロスプラットフォームが前提なので、Linux 版は GTK に乗った重めの構成です。foot は Wayland 専用で小さく速く、hull にいちばん近い端末です。hull はこの間に入ります。

| 軸 | alacritty | ghostty | foot | hull |
| --- | --- | --- | --- | --- |
| 対象 | 全 OS | 全 OS（macOS が中心） | Wayland だけ（sway などのタイル型が中心） | Ubuntu + Wayland（GNOME）だけ。そのぶん層が薄い |
| 描画 | GPU（OpenGL） | GPU | CPU（pixman）で、変わった所だけ描く | GPU（GLES3）で、変わった行だけ描く |
| 速さ | 画面全体が変わるときに強い | 速い | 変化が小さいときに強い | どんな変わり方でも遅くならない。ベンチを公開し、負けたらリリースしない |
| 拡張 | なし（入れない方針） | 設定とシェーダーまで | 外部コマンドへのパイプと、正規表現のヒント（一方向で一度きり） | プラグイン。常駐して、イベントを受け取り、本体に操作を返せる |
| 多重化 | tmux に任せる | タブ・分割を内蔵 | tmux に任せる（サーバーモードあり） | tmux に任せ、tmux の土台として最高にする |

**foot との違い**

foot は検索、URL ヒント、正規表現のヒント、通知、OSC 133 の扱い、IME、kitty keyboard protocol を本体に持っています。機能の数では差がつかないので、次の3つで差をつけます。

- **画面を分けても遅くならない**：foot は変わった所だけを CPU で描くので、変化が小さいときは alacritty より速い。一方で、画面が左右に分かれているとき（tmux の左右分割、vim の行番号、サイドバー）や、長くスクロールするときは全体を描き直し、alacritty より遅くなる（[fuzmare の記事](https://zenn.dev/fuzmare/articles/foot-terminal)、foot 1.13.1 での測定）。tmux で画面を分けるのは hull の普通の使い方なので、GPU と damage tracking でどちらの場合も遅くならないことをねらう。ただしこれは仮説で、今の foot で Phase 0 に測り直す
- **双方向のプラグイン**：foot の拡張は、ある時点のテキストを外のコマンドに一度渡すだけで、画面には何も返せない。hull のプラグインは常駐し、流れてくる出力のハイライトや、状態を追い続ける表示ができる
- **GNOME に馴染む**：foot は GNOME では自分で枠を描くが、設定できるのは色・大きさ・ボタンだけで、デスクトップのダーク設定に自動で追従する仕組みはドキュメントに見当たらない。hull は Ubuntu の標準である GNOME を主な対象にし、見た目と設定の追従まで仕上げる

日本語の扱いは差になりにくいです。foot も IME の変換中の文字をその場に出し、フォールバックは fontconfig で、文字幅は utf8proc で扱います。

拡張を持つ端末には kitty（kittens）と WezTerm（Lua）もありますが、どちらも本体が大きく、拡張は本体と同じプロセスの中で動きます。hull は拡張をプロセスの外で動かし、本体を小さいまま保つことで差をつけます。

### 1. Ubuntu + Wayland 専用で、層を削る

- winit、GTK、クロスプラットフォーム用の抽象を使わず、Wayland と直接話す
- X11、macOS、Windows には対応しない。Ubuntu 24.04 以降は、NVIDIA の環境も含めて Wayland が標準
- 配布は `.deb` / PPA だけ
- 日本語を一級市民として扱う。IME（text-input-v3）の変換中の文字をその場に出し、全角幅と Noto CJK へのフォールバックを最初から正しく作る

### 2. 速さを「主張」でなく「数字」で示す

最初にベンチマークの基盤を作り、同じマシンで alacritty、ghostty、foot を測り続けます。目標は次のとおりです。

| 指標 | 目標 | 測り方 |
| --- | --- | --- |
| 起動してから最初の描画まで | 30ms 未満 | プロセスの起動から、最初のフレームが画面に出るまで（wp_presentation で取る） |
| キーを押してから画面に出るまで | 1フレーム以内 | Phase 0 で決める（Typometer は X11 前提で、Wayland では使えない） |
| アイドル時 | CPU 0%、無駄な wakeup 0回 | 一定時間、何もせずに置いたときの wakeup の回数 |
| メモリ（1窓、スクロールバック1万行） | RSS 20MB 未満 | GPU ドライバの分を含めた値と、含めない値の両方を記録する。1万行は alacritty の既定値に合わせ、条件をそろえる |
| スループット（vtebench） | alacritty と同等以上 | vtebench |
| 変化の型ごとの描画時間 | どの型でも、foot と alacritty の速いほう以上 | vim の描画時間を、次の5つの型で測る：1文字の入力、1行のスクロール、画面全体の変化、左右に分けた状態でのスクロール、tmux で左右に分けた状態でのスクロール |
| バイナリ | 5MB 未満 | strip したリリースビルドの大きさ |

数値は目安です。GPU ドライバの分は環境で大きく変わるので（特に NVIDIA）、Phase 0 で競合を測ったあと、「競合と比べて何割か」の形に決め直します。

**Phase 0 で決め直した目標**（Oct 28, 2026。測り方と結果は [bench.md](bench.md)）

GTX 1660 Ti（NVIDIA）の GNOME で、alacritty 0.16、foot 1.25、ghostty 1.3 と同じ方法で測りました。EGL の初期化だけで 100ms、窓を出してから画面に出るまでに GNOME の側で 25ms ほどかかり、GPU ドライバだけで RSS が 90MB ほどになるので、絶対値の目標のうち「画面に出るまで 30ms」と「RSS 20MB」は、hull の側では満たせません。比べる形に決め直します。

| 指標 | 決め直した目標 | 今の結果 |
| --- | --- | --- |
| 起動 | 最初にバッファを出すまでが、foot と alacritty の速いほうより速い | hull 11ms、foot 31ms、alacritty 148ms（画面に出るまでは 36ms） |
| アイドル | wakeup 0 回、CPU 0 | 0 回、0ms |
| メモリ | GPU ドライバのライブラリを除いた RSS が、GPU で描く端末（alacritty、ghostty）の半分以下 | hull 26MB、alacritty 58MB（CPU で描く foot は 18.5MB） |
| スループット | alacritty 以上 | `cat` で hull 135MB/s、alacritty 93MB/s、foot 151MB/s |
| 変化の型ごとの描画時間 | どの型でも、foot と alacritty の速いほうと誤差（±10%）の範囲 | 5 つの型とも誤差の範囲 |
| バイナリ | 5MB 未満 | 2.8MB |

foot は `cat` のスループットで hull より 1 割ほど速い。差は、履歴から使い回す行を空白で埋めるメモリの書き込み（1 行 76ns）で、セルを小さくすれば縮められる。v1 のあとで取り組みます。

### 3. プラグイン

alacritty が「入れない」と断ってきた機能を、本体を太らせずに使えるようにします。これがいちばんの差別化です。

**原則**

- **プロセスの外で動かす**：プラグインは普通の実行ファイルで、Unix ソケット上の行区切り JSON で話す。どの言語でも書け、落ちても本体は落ちない（i3 や sway の IPC と同じ考え方）。WASM は実行環境が重いので使わない
- **本体が起動する**：設定に書いたプラグインだけを、本体が起動する。どれを信頼したかが設定ファイルで見え、プラグインが落ちたら本体が起動し直せる
- **ホットパスに入れない**：プラグインには PTY の生のバイト列は流さず、解析済みのイベントだけを渡す。本体がプラグインを待つこともない
- **詰まっても本体は困らない**：本体はプラグインごとに上限つきの列を持つ。プラグインの読み出しが遅れて列があふれたら、古いイベントから捨て、捨てた件数をプラグインに知らせる
- **API の面を小さくする**

| イベント（本体 → プラグイン） | アクション（プラグイン → 本体） |
| --- | --- |
| キーバインドの発火 | PTY に書き込む |
| キー入力（キーを受け取っている間だけ） | キー入力を受け取る・返す |
| OSC 133（プロンプトとコマンドの区切り、終了コード） | 画面やスクロールバックのテキストを読む |
| OSC 7（今のディレクトリ）、OSC 9 / 777（通知）、ベル | 指定した範囲をハイライトする |
| タイトルの変更、フォーカス、選択 | オーバーレイに文字を出す（位置、文字、色） |
| | 指定した位置へスクロールする |
| | ウィンドウに注意を向けさせる（urgency / xdg-activation） |
| | クリップボードに書く、URL を開く |
| | 窓の題名の頭に印をつける |

「テキストを読む」「ハイライトする」「スクロールする」「オーバーレイに文字を出す」「キー入力を受け取る」の5つがあれば、検索（入力欄）、URL ヒント（ラベル）、quick-select はすべてプラグインで作れます。検索と URL ヒントを標準プラグインとして同梱し、API が十分かどうかの証明にします。

題名の印は、Claude Code の状態のプラグインが「タイトルに出す」ために足しました。プロトコルの詳細は [plugins.md](plugins.md) にあります。

3つ目の標準プラグインは、foot の一方向の拡張では作れないものにします。**Claude Code の状態**のプラグインで、ベルと OSC 9 を拾い続けて入力待ち・実行中を追い、タイトルと通知に出します。検索と URL ヒントは foot も本体に持っているので、これだけでは foot との違いを示せないためです。

**信頼**：プラグインはユーザーの権限で動き、PTY に書けて画面も読めます。入れたプラグインは、すべて信頼することになります。

## 対象範囲

| 項目 | 対象 | 対象外 |
| --- | --- | --- |
| OS | Ubuntu 24.04 以降 | macOS、Windows、他のディストリビューション（動けばよいが確認しない） |
| ウィンドウシステム | Wayland | X11、XWayland での動作 |

| 配布 | `.deb` / PPA | Flatpak、Snap |

## 本体に入れるもの・入れないもの

**本体に入れる**

- VT の処理：xterm 互換、truecolor、kitty keyboard protocol、`modifyOtherKeys` と CSI u（tmux の extended-keys 用）、synchronized output（mode 2026）、bracketed paste、OSC 52 / 8
- 描画、フォント（フォールバックを含む）、IME
- 選択とコピー、貼り付け
- スクロールバック
- 設定：TOML のファイル1つ。保存すると、そのまま反映する
- キーバインド（本体のアクションか、プラグインの呼び出しに割り当てる）
- プラグインの API

**入れない**

- タブ、分割、セッション（tmux に任せる）
- 検索 UI、URL ヒント（プラグインにする）
- 画像表示、リガチャ（v1 ではやらない）
- GUI の設定画面、テーマのギャラリー

**本体に機能を足すときの基準**：「プラグイン API では作れない」かつ「ほぼ全員が要る」の両方を満たすときだけ足します。

OSC 9 のうち `OSC 9;4` は ConEmu の進捗表示なので、通知としては扱わず、別のイベントにします。

## tmux の中での動き

hull は tmux の中で使われるのが普通だと考えます。tmux は外側の端末に何でも素通しにするわけではないので、次のように割り切ります（Phase 0 に Ubuntu 26.04 の tmux 3.6 で確かめ、表のとおりだった。`bench/tmux_passthrough.py` で確かめられる）。

| hull に届くもの | 届き方 | 標準プラグインの扱い |
| --- | --- | --- |
| ベル、フォーカス、タイトル | tmux の設定（`set-titles`、`focus-events`）で届く | 通知はベルを主にする |
| OSC 52 | `set-clipboard on` で届く | そのまま使える |
| OSC 133 / 7 / 9 / 777 | 普通は届かない。`allow-passthrough` と DCS で包めば届く | 届けば使うが、届かなくても困らない作りにする |
| スクロールバック | 持つのは tmux。hull の側は空 | 検索と quick-select は、見えている画面だけを対象にする |

tmux のスクロールバックや OSC を使いたいプラグインは、自分で tmux に問い合わせます（`tmux capture-pane` や hook）。プラグインは普通の実行ファイルなので、本体を通さずに tmux と話せます。本体は、そのための仕組みを持ちません。

Claude Code は、通知をベルで出すように設定できます。ベルは tmux を素通りするので、通知プラグインの主な手段にします。

## 技術構成（案）

- 言語は Rust
- VT の解析は `vte` クレート。グリッドは自分で作る（alacritty_terminal をそのまま使うと、alacritty の劣化コピーになるため）
- Wayland は smithay-client-toolkit、描画は EGL + GLES3。グリフアトラスとインスタンス描画で、変わった行だけ描く（damage tracking）
- 描画は Wayland のフレームコールバックに合わせ、何も起きていないときは一切動かない
- 窓ごとの状態（グリッド、PTY、描画の状態）をグローバルにしない。あとでサーバーモードが要るとわかったときに、作り直さずに足せるようにする
- フォントの検索とフォールバックは fontconfig を使う（ラスタライズを swash と FreeType のどちらにしても要る）
- GNOME はサーバー側でウィンドウの枠を描かない（xdg-decoration に対応していない）ので、枠はクライアントの側で用意する

## 進め方

1. **Phase 0：ベンチ基盤**。alacritty / ghostty / foot の数字を、手元のマシンで先に取る。fuzmare の記事と同じ手法（vtebench、`cat`、vim の描画時間）を今の foot で測り直し、`footclient` の起動時間と1窓あたりのメモリも測る。入力の遅れの測り方と、tmux が OSC を素通しにするかどうかも、ここで確かめる
2. **Phase 1：最小の端末**。tmux、vim、Claude Code で毎日使える状態にする
3. **Phase 2：プラグイン API と標準プラグイン3つ**（検索、URL ヒント、Claude Code の状態）
4. **Phase 3：公開**。PPA と、ベンチ結果の公開ページ

## 未決事項

- グリフのラスタライズとシェーピング：swash（Rust だけで完結）か、FreeType + HarfBuzz か
- サーバーモード（1プロセスで複数の窓を持ち、フォントとグリフのキャッシュを共有する、foot の `--server` のような方式）：v1 では入れない。tmux を前提にすると開く窓は少なく、得られるものが小さい。しかも、サーバーが落ちるとすべての窓が消え、1つの窓の大量の出力がほかの窓を遅くする（foot の README にある欠点）。Phase 0 で hull 単体の起動時間を `footclient` と比べ、EGL の初期化だけで目標を超える場合に限って考え直す
- ウィンドウの枠：最小限のものを自分で描くか、既存のクレート（sctk-adwaita など）を使うか。バイナリの大きさ（5MB の目標）に効く

## 決めたこと（Oct 28, 2026、作り直しの最初の実装で）

- グリフのラスタライズは **swash** にした。Rust だけで完結し、可変フォントの名前つきインスタンス（太字）とカラー絵文字も扱える。リガチャはやらないので、シェーピングはしない
- ウィンドウの枠は **自分で描く**。GNOME の色（明暗）に合わせた見出しの帯と 3 つのボタンを、端末と同じ GPU の描画で描く。sctk-adwaita などのクレートは使わない（バイナリは strip して 2.8MB）
- サーバーモードは入れない。EGL の初期化が 100ms かかり起動の目標を超えたが、別のスレッドで初期化し、そのあいだは CPU で最初のフレームを出すことで、最初のフレームを出すまでの時間は 5ms にできた（[bench.md](bench.md)）
- 罫線（─ │ ╭ など）とブロック要素は、フォントを使わずに描く。tmux の境界線や Claude Code の枠が隙間なくつながるようにするため
