# hull-terminal Phase 1 実行計画

Sep 27, 2026 · @Coxless

## 概要

Phase 1 のゴールは、Ubuntu で hull-terminal を開くと bash が動き、vim・less・Claude Code が普通に使え、ウィンドウを閉じて開き直しても同じ bash につながる状態にすることです。

描画は GPU（xterm.js の WebGL）を前提にし、WebGL が使えない環境では DOM 描画に自動で切り替えます。

> Oct 12, 2026 追記：Windows への対応はやめ、Ubuntu 専用にしました。Windows 向けのコード、CI、この計画の中の Windows の作業と確認項目は消してあります。

## 範囲

Phase 1 では「普通のターミナルとして使える」ことだけを作り、ブロック表示や履歴の保存は Phase 2 以降に回します。

| 区分 | 内容 |
| --- | --- |
| やる | デーモンが bash を1つ起動し、UI が xterm.js 1つで操作する |
| やる | Unix ソケットでの UI とデーモンの通信 |
| やる | UI を閉じてもデーモンと bash が残り、開き直すと再接続して直前の画面を戻す |
| やる | WebGL 描画と、使えないときの DOM 描画への自動切り替え |
| やる | GitHub Actions でビルドし、簡単な結合テストを回す |
| やらない | ブロック表示、統合スクリプト、OSC 133 の解析（届くかの確認だけ行う） |
| やらない | 下固定の入力欄、サイドバー、複数セッション |
| やらない | SQLite 保存、ピン留め、プロセス保持、終了セッションの再開 |
| やらない | 設定ファイル、Claude Code の入力待ち検知、インストーラー |

## 構成

リポジトリは Cargo ワークスペースと Tauri アプリを1つにまとめ、UI とデーモンが共有するメッセージ定義を独立した crate にします。

```
hull-terminal/
├─ Cargo.toml            ワークスペース
├─ crates/
│  ├─ protocol/          メッセージ定義とフレームの読み書き
│  └─ daemon/            hull-terminal-daemon（PTY とソケット）
├─ app/
│  ├─ src/               フロント（React + TypeScript + Vite）
│  ├─ src-tauri/         Tauri の Rust コア
│  └─ scripts/           配布パッケージにデーモンを入れる準備
└─ .github/workflows/    CI
```

**名前と場所**

| 項目 | 内容 |
| --- | --- |
| アプリ | hull-terminal |
| デーモン | hull-terminal-daemon |
| 接続先 | `$XDG_RUNTIME_DIR/hull-terminal/daemon.sock` |
| 起動する bash | `bash -i`（ログインシェルの設定に従う） |

**通信メッセージ**

フレームは「4バイトの長さ + MessagePack 本体」とし、出力と入力はバイト列のまま送ります。最初に互換性確認用のバージョンを交換します。

| 方向 | メッセージ | 中身 |
| --- | --- | --- |
| UI → デーモン | Hello | プロトコルのバージョン |
| UI → デーモン | Attach | 画面の列数・行数 |
| UI → デーモン | Input | キー入力のバイト列 |
| UI → デーモン | Resize | 新しい列数・行数 |
| UI → デーモン | Detach | 切断の通知（ウィンドウを閉じるとき） |
| デーモン → UI | Welcome | デーモンのバージョン、bash の PID |
| デーモン → UI | Replay | 再接続時に流し直す直近の出力（リングバッファ） |
| デーモン → UI | Output | PTY の出力のバイト列 |
| デーモン → UI | Exited | bash の終了コード |
| デーモン → UI | Error | 続けられない誤り（バージョン違いなど）。このあと切断する |

Tauri の Rust コアからフロントへは、出力を Channel でバイト列のまま渡します。入力とリサイズはフロントからコマンドで受けてデーモンへ送ります。

## 作業計画

作業は8個です。各作業は完了条件を満たしてから次に進みます。

| # | 作業 | 内容 | 完了条件 |
| --- | --- | --- | --- |
| 1 | 土台づくり | Rust・Node・Tauri v2 の前提パッケージを入れ、ワークスペースと React + TypeScript の Tauri アプリを作る。CI でビルドだけ回す | 空のウィンドウが開き、CI が通る |
| 2 | protocol crate | メッセージ定義とフレームの読み書きを作り、単体テストを書く | 往復のテストと、フレームが途中で分かれて届くケースのテストが通る |
| 3 | デーモン | portable-pty で bash を起動し、interprocess でソケットを待ち受けて入出力を中継する。直近の出力をリングバッファに持つ。bash が終わったらデーモンも終わる | テスト用の小さな CLI から `echo hello` を送り、結果が返ってくる |
| 4 | Tauri の Rust コア | デーモンに接続し、いなければ起動して接続し直す。出力を Channel でフロントへ流し、入力とリサイズをコマンドで受ける | UI からデーモンを起動でき、出力がフロントまで届く |
| 5 | フロント | xterm.js に WebGL・fit・unicode11 アドオンを付け、サイズ変更を PTY に伝える。Ctrl+Shift+C / V でコピーと貼り付け。WebGL が使えなければ DOM 描画に切り替える | Ubuntu で ls、vim、less が普通に使える |
| 6 | 再接続 | ウィンドウを閉じるとき Detach を送り、開き直したら Replay で直前の画面を戻す | 閉じて開き直しても `echo $$` が同じ値になる |
| 7 | Ubuntu の確認 | 確認項目を一通り試し、WebKitGTK での日本語入力と WebGL、大量出力時の CPU 使用率を測る | Ubuntu の確認項目がすべて済み、結果を記録してある |
| 8 | CI の結合テスト | デーモンを起動し、`echo` の結果と Exited を受け取るテストを CI に加える | CI の結合テストが通る |

## 確認結果

Oct 11, 2026 時点の結果です。Ubuntu の確認は、次の2つの環境で、アプリを画面に表示し、キー操作を送って画面を撮る方法で行いました。人が手で操作した確認ではありません。

- GPU のない環境：開発用のワークショップ（Ubuntu 24.04、WebKitGTK 2.52）の中の仮想ディスプレイ（Xvfb）
- GPU のある実機：開発機（Ubuntu 26.04、GNOME 50 / Wayland、NVIDIA GeForce GTX 1660 Ti、ibus + Mozc）。ふだんのデスクトップとは別に、画面に出ない GNOME Shell（`gnome-shell --headless`）を同じ GPU の上で起動し、その中で操作した

**自動テスト**

| 対象 | 内容 | 結果 |
| --- | --- | --- |
| protocol crate | メッセージの往復、1バイトずつ分かれて届くフレーム、未知のメッセージの読み飛ばし | 10 件すべて通過 |
| デーモン（単体） | リングバッファ、あふれた部分のモードの復元 | 11 件すべて通過 |
| デーモン（結合） | `echo` の結果と Exited、再接続で同じ PID と画面、切断中の出力、サイズ変更、2万行の出力の順序、OSC 133 の通過 | 11 件すべて通過（25 回くり返して失敗なし） |

**GPU のない環境での確認（ワークショップの仮想ディスプレイ）**

| 項目 | 結果 |
| --- | --- |
| `ls --color`、`git log \| less -R`、256 色と TrueColor | 色付きで正しく表示 |
| vim、htop | 崩れずに動く。終了すると元の画面に戻る |
| ウィンドウのサイズ変更 | 980×640 → 700×420 で `stty size` が `19 96` になり、追従する |
| Ctrl+C、Ctrl+D、Esc | `sleep` の中断、`cat` の終了、vim の操作で届くことを確認 |
| Shift+Enter | アプリが kitty keyboard protocol を有効にすると `CSI 13;2u` で届き、無効に戻すと普通の Enter になる（`cat -v` で確認） |
| 日本語の表示 | 全角・半角カナとも幅がずれない |
| コピーと貼り付け | Ctrl+Shift+C / V とも動く（日本語を含む） |
| 閉じて開き直す | 同じ PID の bash につながり、画面が戻る。vim や htop の実行中に閉じても戻る |
| `exit 3` | 終了コード 3 が表示され、デーモンも終了する。Enter で新しい bash を起動できる |
| 描画 | GPU がない環境（`/dev/dri/renderD*` がない、または `WEBKIT_DISABLE_COMPOSITING_MODE` を指定）では、自動で DOM 描画になり、vim も正しく表示される。`HULL_TERMINAL_RENDERER=webgl` で WebGL（ソフトウェア描画）でも動く。使っている描画方法はステータスバーに出る |
| 配布パッケージ | `.deb` を作って入れ、同梱したデーモンが起動することを確認 |

**GPU のある実機での確認（開発機）**

| 項目 | 結果 |
| --- | --- |
| 描画 | 自動で WebGL になる。`nvidia-smi` で、アプリの描画プロセス（WebKitWebProcess）が GPU を使っていることを確認 |
| Claude Code（v2.1.296） | 起動時の確認画面、入力欄、ロゴとも崩れずに表示される。ウィンドウの最大化と元に戻す操作で、幅いっぱいに描き直される |
| Claude Code でのキー | Shift+Enter で入力欄が改行され、送信されない。Esc 2回と Ctrl+C で入力が消え、Ctrl+C 2回で終了して bash に戻る。↑ で入力欄の行を移動できる |
| サイズ変更 | 最大化で 159×30 → 209×35 になり、`stty size` と `$COLUMNS` が一致する |
| 日本語入力（ibus + Mozc） | 変換中の文字がカーソルの位置に表示され、候補の一覧が出る。スペースで変換、Enter で確定でき、確定の Enter ではコマンドが実行されない。`echo 日本語の入力 ok` を入力して実行できた |
| 非アクティブなウィンドウ | キーボードのフォーカスがなくても、後から出た出力が表示される（下の「見つけて直した不具合」を参照） |

**大量出力（`yes` を流し続ける）**

5秒間の平均です。CPU は1コアを 100% とした値（開発機は 16 スレッド）。どちらの環境でも、メモリは増え続けず、流している間も Ctrl+C が効きます（GPU のない環境で、送ってから停止まで約 0.3 秒。実機は、キーを送る準備の時間を含めて約 1 秒）。

| 環境 | 描画 | 描画プロセスの CPU | アプリ本体の CPU | デーモンの CPU | GPU 使用率 |
| --- | --- | --- | --- | --- | --- |
| GPU のある実機 | WebGL | 117% | 39% | 45% | 29%（待機時 1%） |
| GPU のある実機 | DOM | 127% | 48% | 未計測 | 14% |
| GPU のない環境 | WebGL（ソフトウェア描画） | 212% | 40% | 54% | — |
| GPU のない環境 | DOM | 166% | 36% | 45% | — |

GPU があれば WebGL のほうが CPU は軽く、GPU がなければ DOM のほうが軽いので、いまの選び方（GPU があれば WebGL、なければ DOM）と合っています。ただし `yes` のように流し続ける出力では、どちらの描画でも描画プロセスが1コア以上を使います。出力を間引いて描くなどの軽量化は、まだしていません。

**見つけて直した不具合**

| 不具合 | 原因と対応 |
| --- | --- |
| 開き直したあと、プロンプトに `2RR0;276;0c…` のような文字が打ち込まれる | 流し直した出力に入っている問い合わせ（カーソル位置や色）に端末が応答し、それが bash への入力になっていた。流し直している間は入力を送らない |
| 急に切断すると、直前の入力が bash に届かないことがある | 出力を書けなくなった時点で、届いていた入力ごと捨てていた。入力は読み終えるまで bash に渡す |
| GPU での合成を切った環境で、vim の画面が一部しか出ない | WebGL の画面が正しく更新されない。Rust コアが GPU の有無を調べ、なければ DOM で描く |
| 非アクティブなウィンドウで、最後の出力が表示されない（実機、WebGL） | WebGL の描画が、次に何かを描くまで画面に出ない。カーソルが点滅している間は気づかない。描画が落ち着いたら、もう一度だけ描き直す |
| Claude Code の罫線が画面の幅に足りない（実機） | つないでいる途中で列数が変わると、その知らせがデーモンに届かず、bash 側の列数が古いままだった。つながったあとで今の大きさを送り直す |

**CI（Ubuntu 24.04）**

コミット 4adbc1e と、実機で見つけた不具合を直したあとの 07123d7 で、ジョブ（整形の検査、clippy、ビルド、結合テストを含むテスト）が通りました。

**まだ確認できていないこと**

- Ubuntu：人が実際に使っての確認。上の結果は、キー操作を機械的に送って確かめたもので、ふだんのデスクトップで毎日使ったわけではない。日本語入力の候補の一覧は、カーソルより少し右下に離れて出る

## 決めること・リスク

**Phase 1 の中で決めたこと**

- [x] メッセージの形式：最初に Hello / Welcome でプロトコルのバージョンを交換し、違えばデーモンが Error を返して切断する。メッセージやフィールドを足すだけならバージョンは上げず、受け取った側は解釈できないフレームを読み飛ばす。意味を変えるときだけバージョンを上げる
- [x] 出力の渡し方：Channel でバイト列のまま渡す。続けて届いた出力は 256KB までまとめて1回で渡し、フロントは描き終えた量を Rust コアに知らせる。まだ描かれていない出力が 2MB を超えたら、コアはデーモンからの読み取りを止める。デーモンもクライアントごとの待ち行列がいっぱいになると PTY の読み取りを止めるので、出力しているコマンドが待たされ、メモリにため込まない
- [x] リングバッファの大きさ：1MB
- [x] 再接続で戻す範囲：生の出力を流し直す。あふれて捨てた部分で設定されたモード（代替画面、マウス報告、括弧付き貼り付けなど）は、捨てるときに追っておき、流し直す前に設定し直す。これで vim など全画面アプリの実行中に開き直しても画面が戻る。流し直す出力に含まれる問い合わせ（カーソル位置や色）には、フロントは応答しない

- [x] 描画方法の選び方：GPU が使えれば WebGL、使えなければ DOM。WebKit は描画デバイスの名前を画面側に見せず、GPU がなくても WebGL をソフトウェアで動かすので、画面側からは見分けられない。そこで Rust コアが調べる（Ubuntu では `/dev/dri/renderD*` があるか、`WEBKIT_DISABLE_COMPOSITING_MODE` が指定されていないか）。GPU での合成を切った環境で WebGL を使うと、画面が正しく更新されないことを確認している

**Phase 1 で足したもの**

- Shift+Enter の区別：従来の符号化では Enter と区別できないので、kitty keyboard protocol の有効・無効と問い合わせにだけ応え、修飾キー付きの Enter を `CSI 13;<修飾>u` で送る。ほかのキーは従来の符号化のまま
- ステータスバー：状態、bash の PID、列数×行数、描画方法（WebGL / DOM）を下に表示する。確認項目を目で確かめるためのもの
- 環境変数：`HULL_TERMINAL_SOCKET`（接続先）、`HULL_TERMINAL_SHELL`（起動する bash）、`HULL_TERMINAL_DAEMON`（デーモンの場所）、`HULL_TERMINAL_RENDERER`（`webgl` / `dom`）
- デーモンのログ：`$XDG_RUNTIME_DIR/hull-terminal/daemon.log`

| 大量出力で UI が固まる | 作業7で CPU 使用率を測り、描画をまとめて行う |
