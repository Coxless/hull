# hull のベンチマーク

concept.md の「速さを主張でなく数字で示す」のための、測り方と結果です。
測る道具は [bench/hullbench.py](../bench/hullbench.py) で、どの端末も同じ方法で測ります。

```bash
cargo build --release --workspace
python3 bench/hullbench.py all --terminals hull,alacritty,foot,ghostty
```

窓の大きさ (100x30) とスクロールバック (1 万行) は、どの端末にもオプションで渡してそろえます
(foot の既定は 1000 行。hull には利用者の設定に左右されない設定ファイルを `--config` で渡す)。
ghostty だけは上限をバイト数で決める (`scrollback-limit`、既定 10MB) ので、既定のままにしています。

結果は `bench/results/` に Markdown で書き出します。**画面がついているときに測ってください**
(画面が消えているとコンポジタがフレームを出さず、表示の時刻が測れません)。

## 測り方

| 指標 | 測り方 |
| --- | --- |
| 起動 | **最初のコミット**: WAYLAND_DEBUG の時刻で、起動してから最初にバッファを付けてコミットするまで (全端末で同じ方法)。**画面に出た**: hull だけ、`--bench-startup` で wp_presentation の時刻を取る |
| アイドル | 窓を開いて 5 秒置いたあと、10 秒のあいだの文脈切り替えの数と CPU 時間 (`/proc`) |
| メモリ | スクロールバックを 1 万行埋めたときの RSS。GPU ドライバのライブラリのマッピングを除いた値 (ドライバがヒープに取った分は分けられない)、PSS (共有のページを使っているプロセスの数で割る)、Private (そのプロセスだけが使うページ) も出す |
| スループット | vtebench。別に入れる (`--vtebench` と `--vtebench-benchmarks`) |
| 変化の型ごとの描画時間 | vim で 300 回操作し、redraw までの 1 回あたりの時間。1 文字の入力、1 行のスクロール、画面全体の変化、左右に分けてスクロール、tmux で左右に分けてスクロール |
| 入力の遅れ | Typometer は X11 前提で使えない。hull だけ `HULL_TRACE_LATENCY=1` で、キーのイベントの時刻 (コンポジタの時計) から、そのあとのフレームが画面に出た時刻 (wp_presentation) までを出す。端末をまたいだ比較は、カメラで画面とキーを撮る方法を Phase 3 までに用意する |
| バイナリ | strip したリリースビルドの大きさ |

## 結果 (2026-10-31、v0.3.0)

Ubuntu 26.04 / GNOME (Wayland) / NVIDIA GeForce GTX 1660 Ti (ドライバ 595.99) / 16 スレッド。
alacritty 0.16.1、foot 1.25.0、ghostty 1.3.1 (snap)、tmux 3.6、vim 9.1。
alacritty、foot、tmux、vim は sudo を使わずに `apt-get download` と `dpkg-deb -x` で展開して使った。
スクロールバックは、ghostty を除いて 1 万行にそろえた (2026-10-28 の結果は、foot だけ既定の 1000 行で測っていた)。

### 起動

| 端末 | 最初のコミット (ms) | 画面に出た (ms) | GPU で描いて画面に出た (ms) |
| --- | --- | --- | --- |
| hull | **14.4** | 49.1 | 151.3 |
| alacritty | 142.0 | - | - |
| foot | 31.2 | - | - |
| ghostty | 523.7 | - | - |

10 回の中央値。最初のコミットは WAYLAND_DEBUG の時刻で、どの端末も同じ方法で測る。画面に出た時刻は hull だけ。
hull の最初のコミットは、測るたびに 11〜16ms ほどばらつく。

### アイドル (10 秒)

| 端末 | wakeup | CPU 時間 (ms) |
| --- | --- | --- |
| hull | 0 | 0 |
| alacritty | 12 | 0 |
| foot | 1 | 0 |
| ghostty | 2512 | 360 |

### メモリ (スクロールバック 1 万行)

| 端末 | RSS (MB) | GPU ドライバのライブラリを除く (MB) | PSS (MB) | Private (MB) |
| --- | --- | --- | --- | --- |
| hull | 113.3 | 26.4 | 61.0 | 31.7 |
| alacritty | 147.5 | 58.8 | 91.9 | 62.0 |
| foot | 28.2 | 28.2 | 20.1 | 18.6 |
| ghostty | 262.4 | 192.4 | 255.2 | 252.6 |

RSS はほかのプロセスと共有しているページも数えるので、GPU のドライバを読む端末が大きく出る。
PSS は共有のページを使っているプロセスの数で割った値、Private はそのプロセスだけが使うページ。
foot は CPU で描くので GPU のドライバを読み込まず、リンクするライブラリも小さく、ほとんどが共有されている。

### `cat` で 43.6MB を流しきる時間

| 端末 | 秒 | MB/s |
| --- | --- | --- |
| hull | 0.33 | 134 |
| alacritty | 0.51 | 85 |
| foot | 0.31 | 142 |
| ghostty | 0.91 | 48 |

### vim の描画時間 (1 回あたり ms)

| 端末 | 1 文字の入力 | 1 行のスクロール | 画面全体の変化 | 左右に分けてスクロール | tmux で左右に分けてスクロール |
| --- | --- | --- | --- | --- | --- |
| hull | 0.045 | 0.050 | 2.476 | 0.061 | 0.041 |
| alacritty | 0.042 | 0.048 | 2.451 | 0.062 | 0.041 |
| foot | 0.054 | 0.046 | 2.453 | 0.060 | - |
| ghostty | 0.044 | 0.070 | 2.744 | 0.102 | 0.045 |

測るたびに、どの端末も ±10% ほどばらつく。hull、alacritty、foot は 5 つの型とも誤差の範囲で、
ghostty は「画面全体の変化」と「左右に分けてスクロール」が遅い (foot の tmux の型は、測る道具の都合で取れていない)。

### わかったこと

- **EGL の初期化に 100ms かかる** (NVIDIA。Mesa でも 128ms)。EGL の初期化を別のスレッドで進め、そのあいだに最初のフレーム
  (背景と見出しの帯) を CPU で描いて wl_shm で出す。シェルがプロンプトを出す前の最初のフレームは、どの端末でも空の画面なので、
  見た目は変わらない
- **fontconfig の初期化に 15〜20ms かかる**。前の起動で決まったフォントのファイルと GNOME の設定を `~/.cache/hull/` に覚えておき、
  次からは待たずに最初のフレームを出す (最初のコミットまで 38ms → 5〜11ms)
- **画面に出るまでの残りの 25ms ほどは GNOME の側**。端末どうしの比較は「最初のコミット」で行う
- **PTY は別のスレッドで読む**。描画しているあいだも出力を受け取れる。受け取り側が追いつかないときは、読むのを止めずに
  1 つにまとめてためる (塊の数で区切っていたころは、vim の「画面全体の変化」が 1 割遅かった)
- **履歴に移った行は 1 セル 4 バイトに詰める** (画面の行は 16 バイト)。大量の出力のあいだは詰めず、止まって 1 秒たってからまとめて詰め、
  `malloc_trim` で OS に返す
- **foot との `cat` の差は、端末の中核で文字をセルに書き込む処理**。描画を通さず term クレートだけに同じデータを流すと 0.255 秒で、
  hull 全体 (0.33 秒) の 8 割ほどになる。その内訳は、vte の解析が 0.05 秒、履歴から使い回す行を空白で埋めるのが 0.026 秒、
  残りの 0.17 秒ほどが、vte から 1 文字ずつ受け取ってセルに書く処理 (1 文字 3ns ほど)。色 (SGR) と全角の分は小さい
- **hull の Private (31.7MB) のうち 11MB ほどは NVIDIA のドライバ** (nvidiactl のマッピングと、ライブラリが書き換えたページ)。
  glvnd が Mesa のライブラリ (libLLVM、libgallium) も読み込むので RSS は 45MB 増えるが、ほとんどは共有のページで、Private は 3MB ほど。
  Intel や AMD、nouveau、仮想マシンでは Mesa が要るので、NVIDIA だけに絞ることはしない
- **スクロールバックは、hull のほうが foot より小さい**。foot は 1 万行に 1 行 1KB ほど使い、hull は詰めて 1 万行で 3.6MB ほど

### まだ測っていないもの

- vtebench (Ubuntu のパッケージがない。https://github.com/alacritty/vtebench をビルドして `--vtebench` で渡す)
- 入力の遅れ (`HULL_TRACE_LATENCY=1` で、人がキーを打って測る)
